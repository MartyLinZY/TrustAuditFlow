\section{Discussion and Future Work}

TrustAuditFlow is positioned as an exploratory extension rather than a complete data circulation platform. Its value is in clarifying how a BLoP-style full-node trusted audit system can support a lighter path for routine events without discarding the full-node path. The design also connects components that are often discussed separately: PDP/PoR-style integrity checking, blockchain anchoring, erasure-code recovery, and trust-based node governance.

Several limitations remain. First, the current paper does not implement real TPM, TEE, SGX, or remote attestation. The trust score abstracts BLoP's trusted measurement idea at the software level. Second, the current verification module uses hash sampling as a workflow placeholder; it is not a complete PDP/PoR protocol. Third, the chain confirmation process is modeled in a PBFT-style way and has not yet been deployed on FISCO BCOS, Fabric, Tendermint, or another production consortium-chain platform. Fourth, the paper focuses on block-level and evidence-level integrity. It does not verify the semantic correctness of credit features, privacy-preserving queries, or federated-learning updates.

Future work should proceed in three steps. First, complete the evaluation under a unified environment, comparing full-node confirmation, Merkle batch anchoring, committee confirmation, and the complete TrustAuditFlow design. Second, replace hash sampling with PDP/PoR or zero-knowledge verification to strengthen the cryptographic claim. Third, connect the design to a real consortium chain and a privacy-preserving computation framework so that task logs and result hashes from data circulation workflows can be audited end to end.
